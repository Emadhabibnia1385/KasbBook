## نصب

```bash
curl -fsSL https://raw.githubusercontent.com/Emadhabibnia1385/KasbBook/main/scripts/install.sh | sudo bash
```

دبیان یا اوبونتو، پایتون ۳٫۱۱ به بالا، و داکر برای پایگاه داده. فقط یک چیز
می‌پرسد — توکن ربات — و بقیه را خودش می‌سازد، چون کلید امضایی که کسی تایپش کند
کلیدی است که کسی می‌تواند حدسش بزند. دو بار اجرا کردنش هم بی‌خطر است.

!!! warning "این نسخه بتاست"

    برای نویسنده‌اش در تولید اجرا می‌شود و تست‌هایش کامل‌اند، ولی هنوز دست آدم‌های
    زیاد و دفترهای زیاد نبوده. پشتیبان بگیر — `scripts/backup.sh` این کار را
    برایت می‌کند و چیزی را که نوشته راستی‌آزمایی می‌کند — و
    [نقشهٔ راه](roadmap.md) را بخوان تا بدانی چه چیزی عمداً ساخته نشده.

## چه کار می‌کند

<div class="grid cards" markdown>

-   __دفتر، با دفتر کل واقعی__

    دفترهای شخصی، کسب‌وکار، تیمی و سازمانی زیر یک حساب. هر تراکنش یک سند تراز
    می‌نویسد، پس دفترها را می‌شود *اثبات* کرد، نه فقط خواند.
    [دفتر دوطرفه](double-entry.md).

-   __پولی که دقیق می‌ماند__

    همه‌جا `Decimal`، در پستگرس `NUMERIC(28,4)`، و روی HTTP یک **رشته** — چون
    JSON فقط یک نوع عددی دارد و آن float است، و `12500000.15` از آن رفت‌وبرگشت
    سالم بیرون نمی‌آید.

-   __جلالی، آن‌طور که باید__

    دوره‌ای مثل `۱۴۰۳-۰۵` **پیش از** هر کوئری به بازهٔ میلادی تبدیل می‌شود.
    دیتابیس هرگز مقدار جلالی نمی‌بیند و خواننده هرگز میلادی.

-   __یک حساب، چند پیام‌رسان__

    آی‌دی پیام‌رسان هرگز خودِ حساب نیست — به آن اشاره می‌کند. تلگرامت را از دست
    بده، دفترهایت می‌مانند. [مدل داده](data-model.md).

-   __حقوق برای تیم__

    دوره، سهم اعضا، کارکرد ثبت‌شده، کسر و اضافه، فیش‌هایی که هر ورودی را
    منجمد می‌کنند، پرداخت مرحله‌ای، و خزانه‌ای که پیش از تقسیم سود برداشته
    می‌شود. [حقوق و خزانه](payroll.md).

-   __APIای روی همان قواعد__

    نه یک پیاده‌سازی دوم. ربات و API هر دو همان سرویس‌ها را صدا می‌زنند، پس
    نمی‌شود قاعده‌ای را در یکی رعایت کرد و در دیگری فراموش.
    [رابط برنامه‌نویسی](api.md).

</div>

## چطور سرِ هم شده

```
  تلگرام            بله            روبیکا
      │               │               │
      ▼               ▼               ▼
 ┌─────────────────────────────────────────┐
 │  adapters/     ترجمهٔ پیام               │   نه دیتابیس، نه قاعده
 └───────────────────┬─────────────────────┘
                     ▼
 ┌─────────────────────────────────────────┐
 │  bot/          صفحه‌ها و مسیریابی        │   بدون نام پیام‌رسان
 └───────────────────┬─────────────────────┘
                     │
 ┌───────────────────┼─────────────────────┐
 │  api/  ───────────┤                     │   خواندن، صدا زدن، ترجمهٔ خطا
 └───────────────────┼─────────────────────┘
                     ▼
 ┌─────────────────────────────────────────┐
 │  modules/*/service.py                   │   هر قاعده، دقیقاً یک بار
 └───────────────────┬─────────────────────┘
                     ▼
        PostgreSQL   ·   Redis   ·   Alembic
```

دو مشتری، یک مجموعه قاعده. [چرا درزها این‌جا هستند](architecture.md).

تقریباً در همه‌شان، نشانه جای دیگری را نشان می‌داد.
